<task type="auto">
  <name>Task 1: Create task tracker with completion detection</name>
  <files>internal/task/tracker.go</files>
  <action>
Create TaskTracker in `internal/task/tracker.go` following the pattern from watcher/watcher.go:

1. **TaskTracker struct**:
   - `filePath string` - absolute path to task file
   - `pollInterval time.Duration` - how often to check for changes
   - `previousTasks []Task` - last known state for comparison
   - `listeners []activity.ActivityListener` - activity listeners
   - `mu sync.RWMutex` - protects listeners
   - `cancel context.CancelFunc` - lifecycle control
   - `wg sync.WaitGroup` - for graceful shutdown

2. **NewTracker(filePath string, pollInterval time.Duration) (*TaskTracker, error)**:
   - Resolve absolute path
   - Initialize with empty previousTasks (will be populated on first poll)
   - Don't require file to exist (it's okay if user creates it later)

3. **AddListener(listener activity.ActivityListener)**:
   - Same pattern as watcher

4. **Start(ctx context.Context) error**:
   - Create cancellable context
   - Do initial parse to populate previousTasks (ignore error if file doesn't exist yet)
   - Start poll loop goroutine

5. **Stop()**:
   - Cancel context, wait for goroutine

6. **pollLoop(ctx context.Context)** (private):
   - Ticker at pollInterval
   - On each tick: call checkForCompletions()
   - Exit on context cancellation

7. **checkForCompletions()** (private):
   - Parse current file state with ParseFile
   - If file doesn't exist: clear previousTasks, return
   - Compare current tasks with previousTasks
   - For each task that was uncompleted in previous and completed now: emit TaskComplete activity
   - Update previousTasks = currentTasks

8. **emitTaskComplete(task Task)** (private):
   - Create activity with type TaskComplete
   - Details: "task" = task.Text, "line" = task.Line (as string)
   - Log: "Task completed: [task text]"

Comparison logic:
- Build map of previousTasks by (line, text) tuple
- For each current task: if completed=true and either not in map or was completed=false in map, it's a new completion
- This handles: new tasks being added as already complete (ignore), existing tasks being completed (emit), reordering (by text match)

Edge cases:
- File doesn't exist: store empty state, no error
- File deleted: clear state
- Task text changed: treat as new task (by line+text key)

Integrate TaskTracker into daemon following the pattern from file watcher integration:

1. **Add field to Daemon struct**:
   - `taskTracker *task.TaskTracker`

2. **Add import**:
   - `"github.com/jackyhe0402/daemonflow/internal/task"`

3. **Create startTaskTracker(ctx context.Context) error** (private):
   - Check if d.Config.Task.Enabled, if not log and return nil
   - Resolve task file path: if relative, join with d.Config.WatchDir
   - Create TaskTracker with resolved path and d.Config.Task.PollInterval
   - Add daemon as listener (d implements ActivityListener)
   - Start tracker
   - Store in d.taskTracker
   - Log: "Task tracker monitoring: [path] (poll every [interval])"

4. **Create stopTaskTracker()** (private):
   - If d.taskTracker != nil: call Stop()

5. **Call in runForeground()**:
   - After startFileWatcher, add:
     `if err := d.startTaskTracker(ctx); err != nil { log.Printf("Task tracker not started: %v", err) }`

6. **Call in shutdown sequence**:
   - In signal handler: stopFileWatcher, stopTaskTracker, stopGitMonitor
   - In shutdownChan handler: same order

Shutdown order: file watcher → task tracker → git monitor (less important monitors stop first)
