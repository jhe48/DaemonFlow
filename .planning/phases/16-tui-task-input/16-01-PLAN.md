Wire up the TUI task submission to daemon IPC:

1. In protocol.rs, add types:
```rust
pub const REQUEST_TYPE_ADD_TASK: &str = "add_task";

#[derive(Serialize)]
pub struct AddTaskRequest {
    pub project_path: String,
    pub text: String,
}

#[derive(Deserialize)]
pub struct AddTaskResponse {
    pub success: bool,
    pub message: String,
}
```

2. In client.rs, add method:
```rust
pub fn add_task(&self, project_path: &str, text: &str) -> Result<AddTaskResponse> {
    let request = Request {
        r#type: REQUEST_TYPE_ADD_TASK.to_string(),
        payload: Some(serde_json::to_value(AddTaskRequest {
            project_path: project_path.to_string(),
            text: text.to_string(),
        })?),
    };

    let response = self.send_request(&request)?;

    if !response.success {
        return Err(anyhow::anyhow!("Add task failed: {}", response.error.unwrap_or_default()));
    }

    let data = response.data.ok_or_else(|| anyhow::anyhow!("No response data"))?;
    Ok(serde_json::from_value(data)?)
}
```

3. In app.rs, update `submit_task()`:
```rust
fn submit_task(&mut self) {
    if self.input_buffer.is_empty() {
        return;
    }

    let text = self.input_buffer.clone();
    self.input_buffer.clear();

    // Use empty project_path to use daemon's watch directory
    match self.ipc_client.add_task("", &text) {
        Ok(resp) => {
            if resp.success {
                // Trigger immediate task refresh to show new task
                self.update_tasks();
            } else {
                self.last_error = Some(format!("Failed to add task: {}", resp.message));
            }
        }
        Err(e) => {
            self.last_error = Some(format!("IPC error: {}", e));
        }
    }
}
```

4. Ensure the controls help shows feedback:
   - After successful add, the task list refreshes (update_tasks is called)
   - On error, last_error displays at bottom of screen (existing pattern)

Note: The daemon writes to TASKS.md in its watch directory. The file watcher detects the change and syncs to SQLite. The next update_state() call will show the new task in the TUI list. Natural language parsing (recurring tasks) is handled by the existing Brain integration in the sync pipeline.
